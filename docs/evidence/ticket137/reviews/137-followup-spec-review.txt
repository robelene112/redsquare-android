1. High: accepted admission becomes unrecoverable after invitation expiry.
Requirement: #137 says clients must "survive process loss with original operation identities"; protocol says the app remains pending "Until this accepted control and usable keys arrive".
SpaceClient.kt:285-292 selects the invitation stream while joining_invitation exists; it removes that field only after applying the admission at:509-510. SpacesServiceStore.kt:82-85 requires the invitation still to be unexpired even when its caller is now an admitted member. An owner can accept the guest before expiry, then the guest can stop or remain offline until after expiry. Its original Join is durably accepted, but every refresh is denied before it can receive its Welcome. Sharing a replacement link cannot recover this installation because SpaceClient.kt:116 rejects any second join with saved work. Owner-side invitation renewal does not resolve this pending-join lifecycle. Permit authenticated admitted-member recovery independently of expired bearer authorization, preserving the original device package and operation.

2. Medium: the bounded conversation window still removes a reading anchor on unrelated arrivals.
Requirement: quality plan:52 requires "list reading anchor retained through refresh and return"; :60 requires "no reading-anchor jump from unrelated arrivals".
SpacesAccount.kt:148-149 passes a null window for ordinary reading until Earlier messages explicitly pins one. SpaceClient.kt:402-405 and:415-426 recompute that window from last_content minus49 on each publish. With50 loaded messages, reading the first message while another arrives removes the visible item from the displayed list, so LazyColumn cannot retain its stable key and pixel offset. Saveable list state alone cannot preserve an item the window discarded. Pin the visible window/anchor while reading, and advance it on an explicit latest/send action. The new native return assertion uses only20 populated messages and does not cover this boundary.
