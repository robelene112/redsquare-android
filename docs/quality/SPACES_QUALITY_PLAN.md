# Spaces quality and delivery plan

Status: proposed acceptance contract, 2026-11-17. Requested before specification and prototype. This plan defines required evidence; it does not claim that Spaces, its tests or the two reported fixes already exist. Zero defects cannot be guaranteed. The goal is to prevent avoidable defects, expose uncertainty early and block release on observed failures.

## Delivery order and gates

1. Complete this plan, then publish the coherent specification, then deliver a native, clearly labelled interactive UI prototype for owner review. Prototype work is isolated from the live application and uses only synthetic in-memory data. The owner explicitly requested these three phases in this order.
2. Reproduce and fix composer #132 and embedded-original scrolling #133, sequentially, with failing-then-passing native evidence and their existing acceptance criteria. They block functional Spaces integration. They do not block the isolated design prototype. Neither is fixed by recording its symptoms or by passing an unrelated old suite.
3. Obtain UI feedback against the prototype and record the accepted flows, frames, tokens and motion. Functional implementation tickets are a later owner-requested phase. A prototype verdict is design evidence, never backend or encryption acceptance.
4. Before functional implementation, resolve the named protocol, crypto, persistence and provider decisions in the specification. Establish executable contracts and fixtures at the owned application boundary. Work in small end-to-end increments, one ticket at a time, each usable and independently verifiable. Do not implement several tickets in parallel.
5. Integrate against the frozen complete existing-app regression catalogue, run the required native/profileable/update gates, review both Standards and Spec, then stage a signed candidate, verify its downloaded bytes and promote only after all applicable gates pass. Real-provider, real-device or OEM evidence must be named when absent; emulator results do not establish it.

## Risk register and what would catch the defect

| Failure | Required observation and invariant |
| --- | --- |
| Loaded original becomes a short loader or feed jumps (#133) | Capture frame sequences and stable item ID/geometry during repeated fast scroll out/back, delayed images and history arrival. Loaded content must not regress to initial loading within the same identity. Track a reading anchor plus pixel offset before/after inserts. Inspect all transition frames, not only final screenshots. |
| Old uncertain send locks a new composer (#132) | Reopen/new draft during held original submission, repeated callbacks and process restart. Distinct draft and signed-operation identities; original stays reconcilable, fresh input stays editable, no duplicate submission or stale callback overwrite. |
| Header/status overlaps content, call buttons crowd, IME covers Send | Native screenshots and geometry assertions across compact width, large font, landscape, keyboard and call bar. Persistent layout regions reserve their real space. Transient status is in a defined region, never positioned relative to arbitrary feed children. |
| Wrong Space/channel/account receives an action | Switch A to B while A read/write callbacks are held, change account/node, then release A. No cross-scope content, draft, badge, key, read marker, upload or send. |
| UI claims success before a real side effect | Observe the independent controlled peer, filesystem or platform callback. Queued, transmitting, accepted, unavailable and failed are distinct. No generic red failure treatment for normal pending work. Clipboard success follows actual clipboard completion. |
| Membership or role differs between clients | Independently running signers replay duplicate, delayed and out-of-order events; compare visible membership and permissions after convergence. Only authorized signed actors change roles; exactly one owner; owner transfer requires both parties. |
| Revoked member gets future private content | Send and retrieve real encrypted text, article, file and media-control events before/after revocation; old member cannot read new content. Cache purge alone is not proof. Existing copies are not promised erased. |
| Storage loss, double billing or silent content loss | Crash before/after each durable boundary; repeat receipt/renewal; fill disk/quota; expire provider. One logical operation, explicit consent for costs, original bytes and operation identities preserved, no automatic deletion to make space. |
| Jank grows with message volume | Release-equivalent profileable APK; bounded image decoding, page/query work and background indexing. Repeated scroll, reaction and incoming-update measurements with trace attribution, compared with a frozen baseline. |
| Test machinery passes an incomplete run | Prospective expected-case manifest, observed terminal outcomes, artifact hashes and APK/source identity. A timeout, skipped required case, broken observer or missing partition fails acceptance. Never assemble passing prefixes from different failed runs. |

## Architecture that makes these checks possible

Use immutable, explicit view state for initial loading, cached content with refresh, empty, partial history, offline, denied, archived, pending and recoverable failure. Separate operation lifecycle from screen lifecycle. Loaded content can refresh without discarding usable content; permission removal is a deliberate exception, with truthful rendering. UI must not derive a send outcome from a timer or assume a local mutation proves remote acceptance.

Own Space/channel/account/node identity in the application coordinator. Use stable domain IDs for lazy-list keys, drafts, threads, files and read anchors. Hold no crypto, disk IO, image decoding, network reads or whole-history transformations on the main thread or in repeated composition. Queries and lists are paged; subscriptions and caches are bounded and retired explicitly. Call/audio and transfer ownership are independent of whether their screen is visible. Persistence recovery restores work, never invents a replacement wallet or operation.

Define a signed, versioned Space event contract and authoritative permission evaluation before the UI can mutate real data. Independently evaluated reference fixtures must accompany role/ownership, invitation, revocation and history-key contracts. Prefer a maintained, reviewed encryption implementation; do not invent a new group cryptosystem inside UI code. Wire ciphertext, local at-rest protection and metadata disclosure are separate acceptance claims. Existing plaintext group Chat cannot be made private by hiding its rows.

## Test boundaries, from fast feedback to release evidence

- **Domain contracts:** permission and membership state transitions, invitation expiry/revoke, ownership confirmation, timeout scope, ordering/idempotency, encryption epochs, queued-operation recovery and visibility transitions. Assert public outcomes, not private helper calls. Use deterministic reference clocks/randomness and generated event permutations; retain the failing seed. Add independent expected results, not expectations copied from the reducer under test.
- **Owned application boundary:** real coordinator/repository/persistence/crypto talking to isolated controllable Saito-compatible peers and storage providers. Independently verify signed bytes, received counts, authorization, payload confidentiality and exact recovered files. Each client has separate identity, process and storage. Cover owner, admin, member, nonmember and departed/banned member; parallel operations are test inputs, not parallel implementation tickets.
- **Native rendered UI:** launch the actual Activity and drive taps, Back, keyboard, rotation and scrolling through the normal routes. Include a nonowner/nonadmin account. Semantics checks prove control meaning and focus; screenshots/geometry prove visibility, spacing and reachability. A detached composable or mock screen cannot stand in for the actual integration flow.
- **Real process/OS:** the host deliberately kills the application after observed durable checkpoints, confirms a distinct PID, cold-starts, then verifies identity, draft, queued operation, key/role state and absence of resends. Exercise permission denied/revoked, Home, screen off, notification return, deep link and interrupted picker. Compose recreation alone is not process-death proof.
- **Multi-client protocol and provider compatibility:** independent processes exchange actual versioned envelopes and files. Include current compatible Saito reference clients, older unsupported clients and real provider schema/expiry semantics in controlled rehearsal. Unresolved incompatibility is a named blocker, not permission to silently downgrade privacy or drop existing Chat functionality.

## Native visual acceptance matrix

Keep the full screenshot-state inventory prospective and map every screen/state to its test ID. Baselines require deliberate human/agent visual inspection; do not auto-approve newly generated images.

Core rendered journeys: module entry; My Spaces/Discover/Activity; switcher with categories; invitation/rules/join; public read vs membership; private inaccessible link; chat, threaded reply, reactions and announcement; search; article editor/Markdown/review/reader; files and quota/expiry; prejoin/active/minimized call; members/moderation/log; create/settings/archive/ownership; backup/restore. Each includes loading, populated and relevant empty/error/offline/restricted states. Prototype scenarios demonstrate these states but cannot prove real effects.

Cover Android 10 and 17; widths 320/360/412/600 dp; portrait plus critical landscape; font 100/130/200 percent; light/dark; normal/reduced motion; keyboard open/closed; gesture/three-button navigation and system insets. Use pairwise coverage across ordinary combinations and a mandatory worst-case set: 320dp+200percent, landscape+IME, call bar+IME, long identity+role+badge, delayed media+incoming items. Do not multiply every axis into an unmanageable Cartesian suite. Inspect device models actually used; these width/font variations alone are not Samsung/Xiaomi/OEM proof.

Required UI assertions: controls at least 48dp, accessible label/role/selected state, no clipped primary text/actions, no overlapped controls, sensible reading/focus order, list reading anchor retained through refresh and return, per-channel draft and scroll isolation, pinned status below its intended header with no overlay on messages. Transitions are short, interruptible and responsive to rapid repeated input, with no fixed artificial delay. Reduced motion preserves understandable static feedback. TalkBack exercises switcher, unread count, thread reply, composer, file and call controls.

Capture full frame sequences for channel switching, refreshing, restoring embedded content, opening keyboard, expanding thread, incoming call bar and modal transitions. Use actual frame timestamps; do not infer timings from frame numbers in a variable-rate recording. Sampled screenshots alone cannot pass a no-flicker claim. Clock-controlled Compose tests are useful but must be supplemented by real-time native recordings because synchronization can hide intermediate frames.

## Performance and scale contract

Freeze the fixture volume, device/image/build mode, operation script and thresholds before measuring. The large deterministic dataset has 100 Spaces, 1,000 channels, 100,000 messages across channels, a 10,000-message hot channel, 1,000 file entries and a bounded mixed-media viewport. Measure both cold load and warm cache. Only visible pages are rendered/decoded; history volume must not imply full main-thread scans. Repeat five measured scroll/react/switch runs after one explicit warm-up; retain every run. Investigate traces rather than rerunning until lucky.

Initial acceptance targets on the declared reference environment: local tap feedback p95 <=100ms; no frame >=700ms; <=5percent frames missing the device frame budget during the scripted warm scroll; no reading-anchor jump from unrelated arrivals. Declare actual refresh rate and frame budget, collect p50/p95/p99 and allocation/heap trends, and investigate regression >10percent against the same-environment baseline. A short memory sample is not a leak proof: include 100 switch/open/close cycles, verify subscriptions/jobs return to their known idle bound, and compare retained heap trends after settling. If the reference environment cannot sustain the targets, resolve the cause or explicitly agree a changed contract before release, never edit the threshold after a failed run to manufacture acceptance. Emulator timing is diagnostic; a physical midrange/OEM measurement remains a distinct release qualification.

## Failure and interruption schedule

At each meaningful transaction boundary, schedule: no network, delayed ack, accepted-but-ack-lost, duplicate event, reversed delivery, stale response, node replacement, provider offline/expired/full, source unavailable, permission denied/revoked, process termination and return via a link/notification. Highest-risk crossed cases are mandatory: revoke during upload/key delivery; queued send while switching channel/account; owner transfer during admin change; archive while composing; pending attachment plus keyboard plus call bar; invitation expiry while its preview is open; quota exhausted after file selection; restore with missing history keys; arrival of history during fast scroll.

For each scenario record expected visible state, preserved bytes/IDs, allowed remote effects, cancellation/recovery path and oracle. Ordinary authorization/correctness and privacy tests are in scope; no attack simulations, exploit research or provider-gated cybersecurity work is requested.

## Evidence, review and release stop rules

Each slice has one traceable packet: originating requirement, exact source and APK hashes, native device/build settings, expected/observed case catalogue, screenshots/frame recordings, independent remote receipts and terminal result. Keep unsuccessful observations. Classify environment/observer failures separately but do not count them as passes. Observer fixes have their own source review and a fresh complete affected run; frozen app assertions and goals remain unchanged.

Stop release for any reproducible crash/ANR, data or identity loss, unauthorized action/private-content disclosure, duplicate signed publication/payment, blocked primary flow, missing required case, failed artifact identity or wrong update continuity. Owner-approved minor cosmetic follow-ups must be explicit and do not waive clipping, touch/focus accessibility, misleading state or the accepted prototype flows. The implemented UI must be compared directly against the approved prototype for every core route; a passing semantics suite is insufficient.

Run fast contracts and affected native journeys on each slice; run the complete integrated regression only at integration milestones and the final candidate, or when a shared change requires it. Reuse unchanged dependencies/build outputs. Do not rebuild for fixture text/color/spacing experiments if the prototype already supports runtime changes. Preserve all existing Red Square, Chat, Stack, Talk, Vault, Store and wallet continuity checks. Validate upgrade from beta139 without clearing data, along with ordinary cold install, process recovery and public immutable APK verification. Keep the beta channel unchanged while shipping the separate prototype. Maintain a rollback-compatible prior APK and migration path; no destructive database rollback over later writes.

## References and source observations

- [Android Compose performance guidance](https://developer.android.com/develop/ui/compose/performance/bestpractices): avoid repeated expensive composition work and use stable list identity.
- [Compose synchronization](https://developer.android.com/develop/ui/compose/testing/synchronization): synchronized/virtual-clock assertions do not establish what real-time intermediate frames showed.
- [Android Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview): measure whole native journeys and retain trace output.
- Existing native process, viewport, motion and scroll tools, the complete beta139 acceptance packet, and actual owner reports #132/#133 are the prior art. Current group Chat source explicitly carries plaintext; local encrypted storage is not end-to-end transport protection. Talk's proven three-party media does not prove arbitrary room capacity. Fileshare's online-peer transfer is not a durable community library; normal Vault uploads are provider-readable. These gaps must be resolved, not disguised by the prototype.
