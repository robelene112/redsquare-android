## Existing native boundary

`WalletBalances.assess` fetches bounded HTTPS snapshots but returns only `ImportBalance.UNKNOWN/ZERO/POSITIVE`. It deliberately discards exact UTXOs. `ImportBalance` is an import-risk indicator, not selectable funding. `SaitoTransaction.create/restore` supports one zero-valued input and self-first zero outputs; it cannot create or restore a funded payment. `SaitoPeer` authenticates and supports application RPC/type4 broadcasting, but ignores chain-reference messages. Extend these capabilities deliberately rather than treating a displayed balance as sufficient to send.

## Balance and exact funding

Both pins expose GET `/balance/<validatedActivePublicKey>`, returning ASCII:

```text
<chainTimestamp>-<height>-<64hexBlockHash>.snap
<Base58Owner> <blockId> <transactionOrdinal> <slipIndex> <nolanAmount> <slipType>
```

This is the existing balance **and UTXO** API, not JSON or an Archive query. Always request one valid key, never the unfiltered `/balance/` fallback. Validate response size/completeness, header freshness/nonzero tip, exact owner, valid curve point, u64 coordinates/amounts, u8 index/type, unique locations and checked totals before replacing prior observations. 100000000 Nolan = 1 SAITO. HTTPS establishes a selected-server observation; there is no signed snapshot, row count/checksum, UTXO proof or independent zero proof. [HTTP A/B identical:522](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/node/lib/saito/core/server.ts#L522), [snapshot A/B identical](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/util/balance_snapshot.rs#L56), [currency](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/defs.rs#L5).

Preserve each selected input's owner, amount, block ID, ordinal, original index and type. Full 59-byte UTXO identity is `point33|blockId8|ordinal8|index1|amount8|type1`; wire slip is `point33|amount8|blockId8|ordinal8|index1|type1`, all integers BE. Never substitute the new input-list position for its original index. [Slip encoding, identical A/B:132](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/slip.rs#L132).

Normal0, ATR1, MinerOutput5 and RouterOutput7 are ordinary authorizable input classes. Preserve their types; new recipient/change outputs are Normal0. Exclude stake8, Bound9, P2SH10 and other unsupported special types. Snapshot inclusion alone does not establish wallet eligibility: it excludes Bound/expired rows but can include locked or age-boundary holdings. Core selection's minimum is `tip-genesisPeriod+2` when past that period, otherwise1. Obtain compatible current network parameters/chain context; do not guess genesis period. Subtract durable reservations from every refreshed snapshot. [Selection A:777](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/wallet.rs#L777), [window A:227](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/wallet.rs#L227), [snapshot selection](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/blockchain.rs#L2893).

## Funded transaction

Select positive eligible inputs covering payment+fee, prepend a zero Normal author input, put recipient payment first and author change second, retaining zero change for exact funding. Fee is `sum(inputs)-sum(outputs)`, not a separate field. Parse positive SAITO text exactly with at most eight decimals; use checked u64/BigInteger arithmetic. Never silently round or change an authenticated fee. Default source fee is0, not a fee-free delivery guarantee. The browser metadata is `{module:"Saito",request:"crypto payment",amount:"…",from:sender,to:recipient,hash:stableOperationId,memo:"…"}`; actual transfer value/address comes from slips. Memo is public unless compatible encryption is explicitly implemented. [A constructor:1007](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/wallet.rs#L1007), [B constructor:1052](https://github.com/SaitoTech/saito/blob/214504ecece76d1cd20a245fe4468eccbfca2951/rust/saito-core/src/core/consensus/wallet.rs#L1052), [browser payment:445](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/node/lib/saito/wallet.ts#L445).

Normal transaction type0, replacements1, millisecond timestamp; output indices0,1 assigned before signing. Preimage: `timestamp8|allSignatureSlips|replacements4|type4|exactMessage`; each signature slip is `point33|amount8|index1|type1`. Hash BLAKE3 once, compact low-S secp256k1 signature64. Input block/ordinal coordinates are absent from the signature preimage, so signed identity alone cannot authenticate them. Preserve exact original candidate bytes and reserve full UTXO identities. Maximum255 inputs includes the author zero input. Network header93 plus59 per slip, message bytes and130 per routing hop; type4 broadcast adds the existing author-to-authenticated-peer hop. [Sign/network serializers](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/transaction.rs#L750), [broadcast contract](NATIVE_TRANSACTION_BROADCAST.md).

## Pending and inclusion

Type4 has no correlated acceptance/rejection. Socket enqueue is not confirmation; missing/stale snapshots or missing Archive rows do not prove rejection. Mempool deduplicates signatures and rejects conflicting positive UTXOs. Source wallet selection can mark inputs spent before insufficient-funding failure; snapshot reload marks them unspent without clearing pending transactions. Native must avoid both accounting defects. B also changes pending-balance accounting; source pending totals are not another spendable pool. [Mempool](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/mempool.rs#L139), [B accounting:698](https://github.com/SaitoTech/saito/blob/214504ecece76d1cd20a245fe4468eccbfca2951/rust/saito-core/src/core/consensus/wallet.rs#L698).

For chain observation, the established binary path is:

| Type | Payload after type byte |
| --- | --- |
| 15 KeyList | concatenated watched point33 values |
| 21 RequestBlockchain | knownHeight8,hash32,fork32,syncType1(SPV=1),owner33,keyCount4,keys33 each |
| 22 Blockchain | fixed192-byte tip/ancestor/chunk-boundary header,count4,then count×53-byte references |
| 6 BlockReference;18 GenesisBlockReference | height8,hash32,timestamp8,transactionCount4,goldenTicket1 |
| 17 RequestGenesisBlockReference | empty |

Maximum128 references/chunk; SPV chunk transaction counts are wallet-relevance flags0/1, not full transaction totals. Fetch relevant binary `/lite-block/<hash>/<owner>` from the approved selected origin. Blocks have a389-byte header followed by variable transactions; lite blocks retain relevant full transactions and compressed SPV placeholders. Match original payment signature, author, actual slips, block identity and selected-chain references; track shared ancestors and invalidate orphaned inclusion on reorganization. Fresh SPV bootstrap normally covers only the latest10 blocks, so reconnect after a longer gap needs resumed cursors or an explicit unavailable-history state. Type23's routing handler is empty. [Chain schema, identical A/B](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/network/msg/blockchain.rs#L6), [reference schema](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/network/msg/block.rs#L54), [block serialization](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/block.rs#L2569), [lite route](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/node/lib/saito/core/server.ts#L334).

Describe matching inclusion as backend-reported/observed, not independent full consensus verification or irrevocable finality. Upstream SPV validation skips full block checks. Browser `OnTransactionSent` follows longest-chain processing, not transport. Memento RPC `{request:"memento",data:{publicKey,offset}}` returns unsigned history rows without original transaction bytes or longest-chain filtering; useful history hints, insufficient confirmation/reservation-release proof. [SPV branch](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/rust/saito-core/src/core/consensus/block.rs#L2899), [Memento A:412](https://github.com/SaitoTech/saito/blob/9a4ca7e9442eb5e872168ced361ce741d7d139d7/node/mods/memento/memento.js#L412).

## Native delivery and reference seam

Show receiving public key/copy/QR independently of connectivity. Bind fresh funding, selected backend, reviewed recipient/payment/fee and device authentication to one active identity. Recheck live connectivity and selected state, then atomically persist signed candidate+reservations before any possible broadcast. Cancel only unsent work; after uncertain transmission retain pending/reservations, including restart/import/backend-switch cases. Refresh cannot unlock those inputs. Any explicit retry preserves original bytes; no automatic offline monetary queue. A confirmed transfer can release consumed-input reservations while retaining inclusion evidence and reorg handling. Expired/conflicted/unknown release policy needs actual evidence, not timeout.

Extend the existing pure WASM/Elliptic vector seam, never initialized wallet state. [Earlier executed funded reference](NATIVE_SAITO_TRANSFER.md#executed-pure-funded-reference) supplies literal input coordinates, fee/change, signature and byte hashes; formalize it as an independent fixture, including >2^53 amounts, exact funding, mutation, insufficient/duplicate inputs, and coordinate-versus-signature distinction. Controlled funded peers must additionally verify reservation races, authentication cancellation, process recovery, unknown delivery and reorg status. Synthetic coordinates are not real spendable funds or consensus-admission proof. No backend modification is established as necessary; actual endpoint readiness, network eligibility parameters and native chain reconciliation remain required implementation work.
